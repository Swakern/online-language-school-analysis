# Система управления онлайн-школой иностранных языков

Учебный проект по системному анализу.

## О проекте

Проект посвящён анализу и проектированию информационной системы для онлайн-школы иностранных языков.

Система предназначена для взаимодействия учеников, преподавателей, администраторов и руководства школы. Основные задачи системы — управление расписанием, записью учеников на занятия, домашними заданиями и учебной статистикой.

Проект выполнен в учебных целях для практического освоения инструментов и подходов системного анализа.

## Цель проекта

Цель проекта — пройти основные этапы работы системного аналитика:

- определить заинтересованные стороны;
- выявить основные потребности пользователей;
- сформулировать пользовательские истории;
- определить функциональные и нефункциональные требования;
- сформулировать бизнес-правила;
- описать ключевой бизнес-процесс;
- построить UML-модели;
- описать основной сценарий использования системы;
- подготовить тест-кейсы;
- составить SQL-запросы для работы с данными;
- спроектировать базовые API endpoints.

## User Stories

### Ученик

- Как ученик, я хочу просматривать расписание своих занятий, чтобы готовиться к ним заранее.
- Как ученик, я хочу просматривать домашнее задание в личном кабинете, чтобы выполнять его.
- Как ученик, я хочу записываться на занятия, чтобы планировать своё обучение.

### Преподаватель

- Как преподаватель, я хочу просматривать своё расписание, чтобы готовиться к занятиям.
- Как преподаватель, я хочу вносить домашнее задание, чтобы хранить его в едином месте.

### Администратор

- Как администратор, я хочу просматривать и редактировать расписание учеников, чтобы быстрее записывать учеников и отменять занятия.

### Руководитель

- Как руководитель, я хочу получать статистику уроков, чтобы понимать, что можно усовершенствовать в системе.

## Моделирование

### BPMN

Для процесса «Запись ученика на занятие» разработана BPMN-модель.

Процесс включает:

1. Вход ученика в личный кабинет.
2. Открытие расписания.
3. Выбор занятия.
4. Проверку наличия свободных мест.
5. Подтверждение записи.
6. Создание записи ученика.
7. Обновление количества свободных мест.

При отсутствии свободных мест система сообщает об этом ученику и предлагает выбрать другое занятие.

## Functional Requirements

Основные функциональные требования проекта:

- система должна позволять ученику просматривать расписание;
- система должна позволять ученику записываться на доступные занятия;
- система должна проверять наличие свободных мест;
- система должна предотвращать повторную запись ученика;
- система должна позволять ученику отменять запись с учётом установленного ограничения по времени;
- система должна позволять преподавателю добавлять домашнее задание;
- система должна позволять преподавателю редактировать домашнее задание;
- система должна позволять преподавателю удалять домашнее задание;
- система не должна позволять ученику изменять или удалять домашнее задание;
- система должна позволять администратору управлять расписанием;
- система должна предоставлять руководителю статистику и отчёты.

Подробные требования находятся в папке [requirements](requirements/).

## Non-Functional Requirements

В проекте определены следующие нефункциональные требования:

- личный кабинет должен загружаться не более чем за 2 секунды при стандартной нагрузке;
- доступ к личному кабинету предоставляется только авторизованным пользователям;
- для административного профиля должна использоваться дополнительная проверка при входе;
- система должна корректно работать на различных устройствах;
- интерфейс должен адаптироваться под размер экрана пользователя.

Подробное описание находится в файле [non-functional-requirements.md](requirements/non-functional-requirements.md).

## Business Rules

Основные бизнес-правила:

- ученик может записаться только на занятие, где есть свободные места;
- ученик не может дважды записаться на одно и то же занятие;
- отменённое занятие недоступно для записи;
- только преподаватель может управлять домашним заданием своего занятия;
- ученик может просматривать домашнее задание только для своих занятий;
- пользователь может выполнять только действия, доступные его роли;
- руководитель может просматривать статистику и отчёты;
- преподаватель не может добавить домашнее задание к отменённому занятию;
- администратор не может удалить занятие, на которое уже записаны ученики;
- ученик может отменить запись не позднее чем за 24 часа до начала занятия.

Полный список правил находится в [business-rules.md](requirements/business-rules.md).
